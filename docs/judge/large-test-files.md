# 16 MiBのテストファイル

状態：実装済み。

各入力と期待出力は、圧縮前のUTF-8バイト数で16 MiB（16,777,216バイト）まで保存できる。
入力と期待出力は別ファイルなので、一つのケースでは最大32 MiBになる。
ケース数は100件、テストセット全体は512 MiBまでとする。

たとえば先頭の`500000`と、空白で区切った50万個の`1000000000`を改行付きで置くと、5,500,007バイトになる。
この入力は16 MiBの約33%を使う。

## 保存と転送

64 KiB以下の小さな本文は、従来どおり下書きのJSONへ直接保存する。
一つの本文が64 KiBを超える場合、またはJSON内の全本文が256 KiBを超える場合、ブラウザーは変更した本文をS3へ直接アップロードする。
この区別によって、Lambdaの同期呼び出しに16 MiBの本文を含めずに済む。

APIは署名付きURLを発行する前に、所有者、問題ID、宣言サイズ、SHA-256を記録する。
ブラウザーはチェックサムを固定した署名付きURLで、UTF-8テキストをアップロードする。
完了処理では、APIがS3から本文を読み、実サイズ、SHA-256、UTF-8、NUL不在を検証する。
検証後の下書きには、本文ではなくファイルID、サイズ、SHA-256を保存する。

S3バケットではバージョニングを有効にする。
APIは検証したVersion IDをDBへ保存し、後続の上書きが公開済みテストを変更しないようにする。
完了していないオブジェクトには`status=pending`タグを付け、一日後に削除する。

## 編集と公開

エディタは選択中のケースだけを署名付きURLで読み込む。
ファイル選択とテキスト編集のどちらからでも保存でき、バイト数はUTF-8で表示する。
大きな本文を読み込んでも、サーバー確認済みのブラウザーキャッシュにはファイル参照だけを残す。

公開処理は下書きのファイル参照を固定する。
提出作成時も本文を複製せず、採点ジョブには検証済みオブジェクトのキー、Version ID、サイズ、SHA-256を渡す。
採点ワーカーは各ケースの実行直前に入力と期待出力を取得し、サイズとSHA-256を再検証する。

標準入力と標準出力の上限も16 MiBである。
ワーカーはケースを順番に取得するため、テストセット全体をメモリや一時領域へ同時展開しない。

## ジェネレータ

入力ジェネレータはケース番号を標準入力で受け取り、標準出力から新規ケースの入力を作る。
出力ジェネレータは指定した既存ケースの入力を読み、標準出力で期待出力を置き換える。
生成結果も各ファイル16 MiBまでとし、変更しない既存データを含めて512 MiBまでに制限する。
置き換える古い期待出力のサイズは、生成結果の容量計算から除く。

ワーカーは空でない生成結果をケースごとにS3へ保存し、結果キューにはファイル参照だけを返す。
保存先は`test-files/<所有者ハッシュ>/<問題ID>/generated/<ファイルID>`とし、実行ごとに新しいファイルIDを使う。
空の生成結果は空文字列として返す。
結果の登録時に所有者と容量を確認し、生成時のVersion IDを固定する。
ブラウザーは全件の検証完了後にテストケースを変更するため、生成や検証に失敗しても既存データを保持できる。

利用環境にはマイグレーション009を適用し、API、結果処理ブリッジ、ワーカー、Webを更新する。
Lightsailワーカーには`JUDGE_TEST_DATA_BUCKET`を設定し、`infra/judge`のIAM変更で生成ファイル専用の保存権限を付与する。
ローカルのDockerワーカーは、APIと同じ`TEST_DATA_BUCKET`と、その開発用バケットを読み書きできるAWS認証情報を使う。
新しいバケットやキューの作成は不要である。

## 保存する情報

DBの`test_files`には、所有者、問題ID、S3キー、Version ID、SHA-256、サイズ、検証状態を保存する。
下書きと公開版の各ケースには、表示名と入力および期待出力のファイル参照を保存する。
提出行とSQSメッセージには本文を保存しない。

ケース名は表示用の文字列であり、S3キーには使わない。
ブラウザーから受け取ったファイルIDは、問題の所有者と問題IDに一致する検証済みレコードだけを保存できる。

## 検証

APIとブラウザーは、16 MiBちょうどを受け付け、16 MiBを1バイト超える本文を拒否する。
ブラウザーテストでは、50万個の10桁整数を含む5,500,007バイトの入力について、アップロード、参照保存、再読込を確認する。
採点ワーカーのテストでは、Version ID付き参照の解決と16 MiBの標準入出力上限を確認する。

一括ZIP取り込みと採点用バンドル生成は実装していない。
複数ファイルの取り込み回数や配信時間が問題になった時点で追加する。
