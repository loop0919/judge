# ADR 0001: 採点実行基盤にAWS Fargateを採用する

- 状態：Accepted
- 決定日：2026-09-03

## 背景

採点処理は、提出されたソースコードを一度だけコンパイルし、その成果物を複数のテストケースで使う必要がある。

Judge0を利用した過去の構成では、テストケースごとに実行を依頼したため、同じソースコードを繰り返しコンパイルしていた。
テストケースが増えるほどコンパイル時間と計算資源の消費が重なり、採点全体の待ち時間を押し上げた。

バックエンドはGoで実装し、AWS Lambda上で動かす方針である。
しかし、採点ではユーザーが提出したコードを実行するため、API処理とは異なる分離境界、実行環境、ライフサイクルが要る。

初期の提出形式にはC、C++、Rust、Java、Python、`txt`を含める。
このうちプログラムを実行する五言語では、言語ごとに異なるコンパイラとランタイムを再現可能な形で提供しなければならない。

## 要求

- 一つの提出を一度だけコンパイルし、生成物を全テストケースで再利用できること。
- 提出間でプロセス、ファイル、資格情報を共有しないこと。
- コンパイラとランタイムを含むイメージを言語ごとに固定できること。
- CPU、メモリ、実行時間、出力量、プロセス数を制限できること。
- APIリクエストと採点処理を非同期に分離できること。

## 検討した選択肢

### AWS Lambdaでユーザーコードを実行する

APIと同じ計算基盤へ集約できるため、構成要素は減る。

一方、Lambdaの実行環境は関数の呼び出しをまたいで再利用される可能性があり、提出単位の廃棄を前提にできない。
採点専用イメージ、ネットワーク、プロセス制限の管理もAPI関数へ混在するため、採用しない。

### Judge0を利用する

Judge0はコンパイルと実行に必要な機能を備えている。

しかし、利用経験のある構成ではテストケースごとにコンパイルが発生しており、今回必要な「コンパイル一回、実行複数回」という単位と合わなかった。
採点手順を独自に制御するため、採用しない。

### Amazon ECS on EC2で実行する

ホストを管理できるため、Fargateでは利用できないカーネル機能や特権操作を選択できる。

その代わり、ホストOSの更新、容量計画、提出間の分離をプロジェクト側で管理する必要がある。
初期段階では運用負担が大きいため、採用しない。

### Amazon ECS on AWS Fargateで実行する

Fargateはタスクごとに分離された実行環境を割り当て、タスク定義でCPU、メモリ、イメージ、ネットワークを指定できる。
一つの提出を一つのタスクへ対応させれば、コンパイル済み成果物を同じタスク内で再利用し、終了後に実行環境ごと破棄できる。

ただし、Fargateでは特権コンテナを利用できない。
タスク内のユーザープロセスは、専用UID、リソース制限、システムコール制限を組み合わせて隔離する必要がある。

## 決定

プログラムを実行するジャッジの計算基盤として、Amazon ECS on AWS Fargateを採用する。

一つのFargateタスクは一つの提出だけを処理し、別の提出には再利用しない。

タスク内ではGoで実装した`judge-runner`がソースコードとテストセットを取得し、次の順序で採点する。

1. ソースコードを一度だけコンパイルする。
2. コンパイル済み成果物をタスク内へ保持する。
3. テストケースごとに新しい子プロセスを起動する。
4. 各テストケースの結果を集約する。
5. 採点結果を保存してタスクを終了する。

C、C++、Rust、Java、Pythonをこの実行モデルの対象とする。
`txt`の判定方式はプログラム実行を伴わない可能性があるため、ランタイム方針で別に定める。

Lambdaは提出の受付、採点要求の発行、Fargateタスクの起動、結果反映を担い、ユーザーコードを実行しない。

## 影響

一つの提出につきコンパイルは一回で済み、テストケース数が増えてもコンパイル回数は増えない。
タスクを提出間で再利用しないため、前の提出が残したプロセスやファイルを次の提出が引き継がない。

一方、提出ごとにタスクの起動時間と最低課金時間が発生する。
コンテナ内部のプロセス分離とリソース計測はFargateだけでは完結せず、`judge-runner`側の実装が必要になる。

## 未決事項

- SQSメッセージとFargateタスクの再試行条件。
- ユーザープロセスへ適用するシステムコール制限。
- ソースコードと採点結果を受け渡す方式。
- `txt`提出の判定方式。
- 言語ごとのコンパイラ、ランタイム、利用可能なライブラリ。
