# ADR 0004: 主データベースにPostgreSQLを採用する

- 状態：Accepted
- 決定日：2026-09-09

## 背景

問題作成画面は下書きをブラウザー内へ保存しており、公開問題APIは固定のサンプルを返している。
作者に紐づけて問題を永続化し、別のブラウザーでも一覧の取得と再編集を行えるようにする必要がある。

今後は問題、問題のリビジョン、提出、採点結果を関連づけて保存する。
検索条件や集計方法は開発中に追加する可能性があり、取得方法を初期段階ですべて固定することは難しい。
既存のジャッジ実行モデルとテストセット保存の設計はPostgreSQLを前提としているが、主データベースの選定理由は記録していなかった。

## 検討した選択肢

### PostgreSQL

関連するデータを外部キーで結び、SQLで検索と集計を実装できる。
提出と採点要求のOutboxレコードを同じトランザクションで保存する構成にも適合する。
検索要件が変わる段階では、この柔軟性を優先する。

一方、ホスティング方式、バックアップ、スキーマの移行手順とLambdaからの接続数管理を設計する必要がある。

### Amazon DynamoDB

取得方法に合わせてキーとインデックスを設計することで、定型の読み書きをスケールさせられる。
サーバーや接続プールの管理が不要であり、Lambdaと組み合わせる利点がある。

関連データも保存できるが、検索方法の追加に伴ってインデックスやデータの持ち方を見直すことがある。
今回は検索と集計の柔軟性を優先し、主データベースには採用しない。

## 決定

OpenOJの主データベースにPostgreSQLを採用する。
問題の下書き、作者との関連、公開状態、問題のリビジョン、提出と採点結果の永続化に用いる。
テストセットの実体はADR 0003に従ってAmazon S3へ保存し、PostgreSQLにはその参照とメタデータを保持する。

最初の実装対象は、認証済みユーザーによる問題の保存、自分の問題の一覧取得と再編集とする。
保存APIでは認証情報を検証し、保存対象の所有者をサーバー側で判定する。

## 影響と未決事項

この決定はDB製品の選定であり、DB接続や保存APIの実装完了を意味しない。
実装時に次を決める。

- PostgreSQLのホスティング方式、バージョンと運用費用。
- Lambdaからの接続方式、接続数の上限と資格情報の管理。
- ローカル開発用DBの起動方法とスキーマの移行手順。
- 認証済みユーザーの識別と所有者によるアクセス制御。
- ブラウザー内の既存下書きをDBへ移行する操作。
- 同時編集による上書きを検出する方法。
